## 🎬 Opening Story: The Emperor's Problem

Long ago, an emperor needed to count gold coins in his treasury — **1 million coins**!

**Approach 1: Do it himself**
Count one by one... would take months!

**Approach 2: The Smart Way (Divide & Conquer)**

```
Emperor's Strategy:
━━━━━━━━━━━━━━━━━━

Step 1: DIVIDE the coins into 2 equal piles
        Give each pile to a trusted minister

Step 2: Each MINISTER divides their pile into 2
        Give each to a governor

Step 3: Each GOVERNOR divides into 2
        Give each to a clerk

... Keep dividing until each person has just a FEW coins

Step 4: Everyone COUNTS their tiny pile (CONQUER - base case)

Step 5: COMBINE results back up the hierarchy
        Clerk reports → Governor sums → Minister sums → Emperor gets total!
```

**Result:** Instead of 1 person doing 1 million operations, thousands of people each do just a few operations simultaneously. The **combination** is just simple addition!

This is **Divide & Conquer** — the most powerful algorithmic strategy!

# 🎯 Part 1: Understanding Divide & Conquer

## What is Divide & Conquer?

> **Divide & Conquer** is an algorithm design paradigm that:
>
> 1. **DIVIDES** the problem into smaller subproblems
> 2. **CONQUERS** each subproblem recursively
> 3. **COMBINES** solutions to get the final answer

## The D&C Template

```
DIVIDE_AND_CONQUER(problem):

    // BASE CASE: Problem small enough to solve directly
    if problem is small enough:
        return direct_solution(problem)

    // DIVIDE: Break into smaller subproblems
    subproblems = divide(problem)

    // CONQUER: Recursively solve each subproblem
    solutions = []
    for each subproblem:
        solutions.append(DIVIDE_AND_CONQUER(subproblem))

    // COMBINE: Merge solutions into final answer
    return combine(solutions)
```

# 🔍 Part 2: Binary Search

## The Story: Finding a Word in Dictionary

Imagine finding "PYTHON" in a 1000-page dictionary.

**Naive Approach:** Start from page 1, check each page... O(n)

**Smart Approach (Binary Search):**

1. Open to middle (page 500) — "M words"
2. "P" comes after "M" → search right half (pages 501-1000)
3. Open middle of right half (page 750) — "R words"
4. "P" comes before "R" → search left half (pages 501-749)
5. Keep halving... find "PYTHON" in ~10 steps instead of 1000!

```
Dictionary Search Animation:

Search for "PYTHON" (P = 16th letter)

Step 1: [A─────────────M─────────────Z]
                       ↑
                    page 500
                    "M" (13th)
                    P > M → go RIGHT

Step 2:             [N─────────R─────────Z]
                              ↑
                           page 750
                           "R" (18th)
                           P < R → go LEFT

Step 3:             [N────P────Q]
                          ↑
                       page 625
                       "P" (16th)
                       FOUND! ✓
```

## Binary Search: Prerequisites

> ⚠️ **IMPORTANT:** Binary Search ONLY works on **SORTED** arrays!

## The Algorithm

```
BINARY_SEARCH(arr, target, low, high):

    // BASE CASE: Element not found
    if low > high:
        return -1

    // DIVIDE: Find middle
    mid = low + (high - low) / 2    // Avoids integer overflow

    // CONQUER: Check middle element
    if arr[mid] == target:
        return mid                   // Found!

    else if arr[mid] > target:
        // Target in LEFT half
        return BINARY_SEARCH(arr, target, low, mid - 1)

    else:
        // Target in RIGHT half
        return BINARY_SEARCH(arr, target, mid + 1, high)
```

## Binary Search: Iterative Version

```python
def binary_search_iterative(arr, target):
    low = 0
    high = len(arr) - 1

    while low <= high:
        mid = low + (high - low) // 2

        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1

    return -1  # Not found
```

## Time Complexity Analysis

```
How many times can we halve n before reaching 1?

n → n/2 → n/4 → n/8 → ... → 1

After k divisions: n / 2^k = 1
                   n = 2^k
                   k = log₂(n)

Each step: O(1) comparison
Number of steps: O(log n)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Total Time: O(log n)
```

**Recurrence Relation:**

```
T(n) = T(n/2) + O(1)
       ↑         ↑
   Recursive   Comparison
   call on     at each
   half        step
```

# 📊 Part 3: Merge Sort

## The Story: Sorting Exam Papers

Imagine a professor with 1000 unsorted exam papers needs to arrange them by roll number.

**Naive way:** Compare and swap repeatedly... O(n²) — too slow!

**Merge Sort way:**

1. **DIVIDE:** Split pile into two halves
2. Give each half to a TA (Teaching Assistant)
3. Each TA **recursively** splits and sorts their pile
4. **COMBINE:** Merge the sorted halves back together

The magic? **Merging two sorted piles is FAST!**

## The Merge Sort Algorithm

```
MERGE_SORT(arr, left, right):

    // BASE CASE: Single element or empty
    if left >= right:
        return

    // DIVIDE: Find middle point
    mid = left + (right - left) / 2

    // CONQUER: Recursively sort both halves
    MERGE_SORT(arr, left, mid)       // Sort left half
    MERGE_SORT(arr, mid + 1, right)  // Sort right half

    // COMBINE: Merge the sorted halves
    MERGE(arr, left, mid, right)
```

## The MERGE Procedure (The Heart of Merge Sort)

```
MERGE(arr, left, mid, right):

    // Step 1: Create temporary arrays
    n1 = mid - left + 1          // Size of left subarray
    n2 = right - mid             // Size of right subarray

    L[0...n1-1] = arr[left...mid]      // Copy left half
    R[0...n2-1] = arr[mid+1...right]   // Copy right half

    // Step 2: Merge back into arr[]
    i = 0       // Index for L[]
    j = 0       // Index for R[]
    k = left    // Index for arr[]

    while i < n1 AND j < n2:
        if L[i] <= R[j]:
            arr[k] = L[i]
            i++
        else:
            arr[k] = R[j]
            j++
        k++

    // Step 3: Copy remaining elements
    while i < n1:
        arr[k] = L[i]
        i++
        k++

    while j < n2:
        arr[k] = R[j]
        j++
        k++
```

# 📐 Part 4: Recurrence Relations & Master Theorem

## What is a Recurrence Relation?

> A **recurrence relation** expresses the running time of a recursive algorithm in terms of the running time on smaller inputs.

## Merge Sort Recurrence

```
T(n) = 2T(n/2) + O(n)
       ↑           ↑
       │           └── Time to MERGE two halves (linear scan)
       │
       └── Two recursive calls on half-sized problems


Breaking it down:
━━━━━━━━━━━━━━━━

              MERGE_SORT(n)
             /            \
            /              \
     MERGE_SORT(n/2)   MERGE_SORT(n/2)     → 2 × T(n/2)
            \              /
             \            /
              MERGE(n)                      → O(n) work
```

## The Master Theorem

The Master Theorem provides a cookbook solution for recurrences of the form:

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│           T(n) = aT(n/b) + f(n)                                 │
│                                                                 │
│   where:                                                        │
│   • a ≥ 1 (number of subproblems)                               │
│   • b > 1 (factor by which input size shrinks)                  │
│   • f(n) = work done outside recursive calls                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Master Theorem: The Three Cases

First, compute the **critical exponent**:

```
p = log_b(a)
```

Then compare f(n) with n^p:

```
┌─────────────────────────────────────────────────────────────────┐
│                    MASTER THEOREM CASES                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ CASE 1: f(n) = O(n^c) where c < log_b(a)                        │
│         ────────────────────────────────                        │
│         f(n) grows SLOWER than n^p                              │
│         Recursion dominates                                     │
│                                                                 │
│         Solution: T(n) = Θ(n^(log_b(a)))                        │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ CASE 2: f(n) = Θ(n^c) where c = log_b(a)                        │
│         ────────────────────────────────                        │
│         f(n) grows at SAME rate as n^p                          │
│         Both contribute equally                                 │
│                                                                 │
│         Solution: T(n) = Θ(n^c × log n)                         │
│                        = Θ(n^(log_b(a)) × log n)                │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ CASE 3: f(n) = Ω(n^c) where c > log_b(a)                        │
│         ────────────────────────────────                        │
│         f(n) grows FASTER than n^p                              │
│         Combine step dominates                                  │
│         (Also needs regularity condition)                       │
│                                                                 │
│         Solution: T(n) = Θ(f(n))                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Visual Understanding of Master Theorem

```
                            Tree View
                            ─────────
                               f(n)
                              / | \
                         a children, each size n/b
                            /  |  \
                       f(n/b) ... f(n/b)    ← a copies
                        /|\       /|\
                       ... ...   ... ...


                Level 0:  f(n)           → f(n) work
                Level 1:  a × f(n/b)     → a × f(n/b) work
                Level 2:  a² × f(n/b²)   → a² × f(n/b²) work
                   ...
                Level k:  a^k × f(n/b^k) → leaves at n/b^k = 1


CASE 1: Work INCREASES as we go down
        Leaves dominate → T(n) = Θ(n^(log_b(a)))

        Level work:  ●
                     ●●
                     ●●●●
                     ●●●●●●●●   ← Most work at bottom

CASE 2: Work SAME at each level
        All levels contribute equally → T(n) = Θ(n^p × log n)

        Level work:  ●●●●
                     ●●●●
                     ●●●●
                     ●●●●       ← Equal work × log n levels

CASE 3: Work DECREASES as we go down
        Root dominates → T(n) = Θ(f(n))

        Level work:  ●●●●●●●●   ← Most work at top
                     ●●●●
                     ●●
                     ●
```

# 🔬 Merge Sort Complexity Using Master Theorem

## Step-by-Step Derivation

**Recurrence:** `T(n) = 2T(n/2) + n`

### Step 1: Identify Parameters

```
T(n) = 2T(n/2) + n

Comparing with T(n) = aT(n/b) + f(n):

• a = 2  (number of subproblems)
• b = 2  (size reduction factor)
• f(n) = n (work to merge)
```

### Step 2: Calculate Critical Exponent

```
p = log_b(a)
  = log₂(2)
  = 1
```

### Step 3: Compare f(n) with n^p

```
f(n) = n = n¹

n^p = n¹

f(n) = Θ(n¹) = Θ(n^p)

Since c = p = 1, this is CASE 2!
```

### Step 4: Apply Case 2 Formula

```
T(n) = Θ(n^p × log n)
     = Θ(n¹ × log n)
     = Θ(n log n)
```

### Verification: Recursion Tree Method

```
                        WORK AT EACH LEVEL
                        ───────────────────

Level 0:        n                           → n work
               / \
Level 1:    n/2   n/2                       → n/2 + n/2 = n work
            /\     /\
Level 2:  n/4 n/4 n/4 n/4                   → 4 × n/4 = n work
           ...............
Level k:  1  1  1  1 ... 1  (n leaves)      → n × 1 = n work


Total levels = log₂(n)
Work per level = n
━━━━━━━━━━━━━━━━━━━━━━━
Total work = n × log₂(n) = O(n log n) ✓
```

### Visual Proof

```
                    n                    ─┐
                   / \                    │
                 n/2  n/2                 │
                / \   / \                 │  log₂(n) levels
              n/4 n/4 n/4 n/4             │
               |   |   |   |              │
              ...  ... ... ...            │
              1 1 1 1 ... 1 1 1 1        ─┘
              └─────┬─────────┘
                  n leaves

Work per level = n (always!)
Number of levels = log₂(n)

Total = n + n + n + ... (log n times)
      = n × log n
      = O(n log n) ✓
```

# 📝 Important Points for MCA Exam

## Key Definitions

### Divide & Conquer

> A design paradigm that divides problem into subproblems, solves them recursively, and combines solutions.

### Recurrence Relation

> Mathematical equation that defines function in terms of its value on smaller inputs.

### Master Theorem

> A formula to solve recurrences of form T(n) = aT(n/b) + f(n).

## Formulas to Remember

```
Binary Search:
  T(n) = T(n/2) + O(1)
  Solution: O(log n)

Merge Sort:
  T(n) = 2T(n/2) + O(n)
  Solution: O(n log n)

Master Theorem (T(n) = aT(n/b) + f(n)):
  p = log_b(a)
  Case 1: f(n) < n^p → T(n) = Θ(n^p)
  Case 2: f(n) = n^p → T(n) = Θ(n^p log n)
  Case 3: f(n) > n^p → T(n) = Θ(f(n))
```

## Common Exam Questions

1. **Trace merge sort on given array**
   - Show divide tree and merge steps

2. **Derive complexity using Master Theorem**
   - Identify a, b, f(n), calculate p, determine case

3. **Write merge procedure**
   - Two-pointer technique with temporary arrays

4. **Compare D&C with Dynamic Programming**
   - D&C: Independent subproblems
   - DP: Overlapping subproblems

## Quick Revision Checklist

```
✅ D&C = Divide + Conquer + Combine
✅ Binary Search: O(log n), requires sorted array
✅ Merge Sort: O(n log n) always, O(n) space
✅ Merge procedure uses two-pointer technique
✅ Recurrence: T(n) = 2T(n/2) + n for merge sort
✅ Master Theorem: 3 cases based on comparing f(n) with n^p
✅ p = log_b(a) is the critical exponent
✅ Merge sort is stable, not in-place
```
