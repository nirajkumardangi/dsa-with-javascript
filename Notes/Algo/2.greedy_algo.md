# Greedy Algorithms & MST: The Complete Guide 🎯

---

## 🎬 Opening Story: The Hungry Traveler

Imagine you're on a road trip with limited fuel. At each junction, you see signs showing distances to different gas stations. You're running low on fuel and need to make decisions FAST.

**Strategy 1 (Exhaustive):** Calculate ALL possible routes, compare total distances, pick the best.
_Problem: You'll run out of fuel while calculating!_

**Strategy 2 (Greedy):** At each junction, just go to the NEAREST gas station.
_Fast decision, might not be globally optimal, but gets you somewhere!_

This is the essence of **Greedy Algorithms** — make the best choice RIGHT NOW, hope it leads to the best overall solution!

# 🟢 Part 1: Greedy Algorithms

## What is a Greedy Algorithm?

> A **Greedy Algorithm** builds a solution piece by piece, always choosing the next piece that offers the **most immediate benefit** (local optimum), hoping this leads to a **global optimum**.

## The Greedy Philosophy

```
┌─────────────────────────────────────────────────────────────┐
│                    GREEDY MINDSET                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   "Don't look back, don't plan too far ahead.               │
│    Just pick the BEST option available RIGHT NOW."          │
│                                                             │
│   ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐                  │
│   │Step │ →  │Step │ →  │Step │ →  │Step │ → SOLUTION       │
│   │  1  │    │  2  │    │  3  │    │  4  │                  │
│   └─────┘    └─────┘    └─────┘    └─────┘                  │
│      ↓          ↓          ↓          ↓                     │
│   Pick       Pick       Pick       Pick                     │
│   BEST       BEST       BEST       BEST                     │
│   now        now        now        now                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## General Greedy Algorithm Structure

```
GreedyAlgorithm(problem):
    solution = empty

    while problem is not solved:
        1. SELECT: Choose the best available option (greedy choice)
        2. FEASIBILITY: Check if it can be added to solution
        3. INCLUDE: If feasible, add it to solution

    return solution
```

## When Does Greedy Work?

Greedy algorithms work when the problem has:

### 1. Greedy Choice Property

> A global optimum can be reached by making locally optimal choices.

### 2. Optimal Substructure

> An optimal solution contains optimal solutions to subproblems.

## Real-World Greedy Examples

| Problem                               | Greedy Choice                    | Works? |
| ------------------------------------- | -------------------------------- | ------ |
| Coin Change (standard denominations)  | Pick largest coin first          | ✅ Yes |
| Coin Change (arbitrary denominations) | Pick largest coin first          | ❌ No  |
| Activity Selection                    | Pick earliest finishing activity | ✅ Yes |
| Fractional Knapsack                   | Pick highest value/weight ratio  | ✅ Yes |
| 0/1 Knapsack                          | Pick highest value/weight ratio  | ❌ No  |
| MST (Prim's, Kruskal's)               | Pick minimum weight edge         | ✅ Yes |

# 🎒 Part 2: Fractional Knapsack Problem

## The Story: The Smart Thief

Imagine you're a thief who broke into a spice merchant's warehouse. You have a bag that can carry **50 kg**. You find:

```
┌─────────────────────────────────────────────────────────┐
│                    WAREHOUSE                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   🧂 Saffron        💎 Gold Dust      🫚 Rare Pepper     │
│   Weight: 10 kg     Weight: 20 kg     Weight: 30 kg     │
│   Value: ₹600       Value: ₹1000      Value: ₹1200      │
│                                                         │
│   Value/kg: ₹60     Value/kg: ₹50     Value/kg: ₹40     │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**The twist:** These are powders/granules — you can take FRACTIONS!

**Your bag capacity:** 50 kg

**Question:** How do you maximize your loot?

## Fractional Knapsack: Formal Definition

> **Given:** n items, each with weight wᵢ and value vᵢ, and a knapsack of capacity W.
>
> **Constraint:** You can take fractions of items (0 to 100% of any item).
>
> **Goal:** Maximize total value without exceeding capacity W.

## The Greedy Strategy

**Key Insight:** Since we can take fractions, we should prioritize items that give **maximum value per unit weight**!

```
Greedy Choice: Always pick the item with highest (value/weight) ratio
```

## Algorithm: Step by Step

```
FRACTIONAL_KNAPSACK(items[], n, W):

    // Step 1: Calculate value-to-weight ratio for each item
    for i = 1 to n:
        ratio[i] = value[i] / weight[i]

    // Step 2: Sort items by ratio in DECREASING order
    Sort items by ratio (descending)

    // Step 3: Greedily fill the knapsack
    totalValue = 0
    remainingCapacity = W

    for each item in sorted order:
        if item.weight <= remainingCapacity:
            // Take the whole item
            take 100% of item
            totalValue += item.value
            remainingCapacity -= item.weight
        else:
            // Take fraction of item
            fraction = remainingCapacity / item.weight
            totalValue += fraction × item.value
            remainingCapacity = 0
            break    // Knapsack is full

    return totalValue
```

**Given:**


## Time Complexity Analysis

```
Step 1: Calculate ratios     → O(n)
Step 2: Sort by ratio        → O(n log n)
Step 3: Greedy selection     → O(n)
─────────────────────────────────────────
Total:                       → O(n log n)
```

## Why Greedy Works Here

```
Key Insight: Since fractions are allowed, there's NO penalty for
             taking part of a high-value item.

If value/weight ratio of A > B, then:
- Every gram of A is more valuable than every gram of B
- We should ALWAYS prefer A over B
- No "what if" scenarios to consider!
```

# ⚔️ Fractional vs 0/1 Knapsack: The Epic Comparison

## The Core Difference

```
┌─────────────────────────────────────────────────────────────┐
│                FRACTIONAL KNAPSACK                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  "Take ANY fraction of an item"                             │
│                                                             │
│  Items are DIVISIBLE (like gold dust, water, rice)          │
│                                                             │
│  🥛 Can pour 0.7 liters of milk                             │
│  ⚖️ Can take 2.5 kg of sugar                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                  0/1 KNAPSACK                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  "Take it completely OR leave it completely"                │
│                                                             │
│  Items are INDIVISIBLE (like laptop, phone, book)           │
│                                                             │
│  💻 Can't take half a laptop!                               │
│  📱 Can't take 0.3 of a phone!                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## Why Greedy FAILS for 0/1 Knapsack

### Counter-Example

```
Items:    A          B
Weight:   10 kg      20 kg
Value:    ₹60        ₹100
Capacity: W = 20 kg

Ratios:
A: 60/10 = ₹6 per kg  ⭐ HIGHER
B: 100/20 = ₹5 per kg
```

**Greedy Choice:** Pick A first (higher ratio)

```
Greedy Solution:
├── Take A: weight=10, value=₹60
├── Remaining capacity: 10 kg
├── Item B needs 20 kg — doesn't fit!
└── Total Value: ₹60 ❌

Optimal Solution:
├── Take B: weight=20, value=₹100
├── Remaining capacity: 0 kg
└── Total Value: ₹100 ✅
```

**The Problem:** By greedily taking A, we "blocked" ourselves from taking the more valuable B!

### Visual Explanation

```
GREEDY APPROACH (FAILS):
┌────────────────────┐
│████A████│  empty   │  Value = ₹60
│  10 kg  │  10 kg   │
└────────────────────┘
  Can't fit B (needs 20 kg)!

OPTIMAL APPROACH:
┌────────────────────┐
│██████████B█████████│  Value = ₹100 ✅
│       20 kg        │
└────────────────────┘
```

## Complete Comparison Table

| Aspect                 | Fractional Knapsack         | 0/1 Knapsack            |
| ---------------------- | --------------------------- | ----------------------- |
| **Item Selection**     | Can take fractions (0 to 1) | All or nothing (0 or 1) |
| **Approach**           | Greedy                      | Dynamic Programming     |
| **Time Complexity**    | O(n log n)                  | O(n × W)                |
| **Space Complexity**   | O(1) or O(n)                | O(n × W) or O(W)        |
| **Greedy Works?**      | ✅ Yes, always optimal      | ❌ No, may fail         |
| **Real-world Example** | Loading cargo (sand, oil)   | Packing suitcase        |
| **Difficulty**         | Easier                      | Harder                  |

## Why Does 0/1 Need Dynamic Programming?

```
0/1 Knapsack has OVERLAPPING SUBPROBLEMS:

                    Include item 1?
                    /            \
                 YES              NO
                 /                  \
        Include item 2?        Include item 2?
         /        \              /        \
       YES        NO           YES        NO
       ...        ...          ...        ...

Same subproblems appear multiple times!
→ Need memoization/DP to avoid recalculation
```

# 🌲 Part 3: Minimum Spanning Tree (MST)

## The Story: Connecting Villages

Imagine you're a government planner. You need to connect 6 villages with roads. Building roads between every pair of villages is expensive.

**Goal:** Connect ALL villages with MINIMUM total road length.

```
        Village Layout with ALL possible roads:

              A ----5---- B
             /|\         /|\
           6/ | \3     4/ | \2
           /  |  \     /  |  \
          C   7   D---8---E   F
           \  |  /     \  |  /
           9\ | /1     5\ | /3
             \|/         \|/
              G----4-----H

Too many roads! We need only enough to connect everyone.
```

## What is a Spanning Tree?

> A **Spanning Tree** of a graph G is a subgraph that:
>
> 1. Includes ALL vertices of G
> 2. Is a TREE (connected and no cycles)
> 3. Has exactly (V - 1) edges for V vertices

```
Original Graph (6 vertices, many edges):

    A───B
   /|\ /|\
  C─D─E─F
   \|/\|/
    G───H

One Possible Spanning Tree (6 vertices, 5 edges):

    A───B
    |   |
  C─D   E─F
    |
    G───H
```

## What is a Minimum Spanning Tree?

> A **Minimum Spanning Tree (MST)** is a spanning tree with the **minimum possible total edge weight**.

```
Weighted Graph:

      1     2
  A───B───C
  |   |   |
 3|  4|  5|
  |   |   |
  D───E───F
    2   1

MST (Total weight = 1+2+2+1+3 = 9):

      1     2
  A───B───C
  |
 3|      1|
  |       |
  D───E───F
    2
```

## Why MST Matters (Real Applications)

| Application      | Vertices    | Edges       | Weight            |
| ---------------- | ----------- | ----------- | ----------------- |
| Network Design   | Computers   | Cables      | Cable length/cost |
| Road Planning    | Cities      | Roads       | Distance/cost     |
| Electrical Grids | Houses      | Wires       | Wire length       |
| Cluster Analysis | Data points | Connections | Similarity        |

# 🔷 Prim's Algorithm

## The Intuition: Growing a Tree

Think of Prim's like growing a plant:

1. Start with a **seed** (any vertex)
2. At each step, **grow** by adding the shortest branch to a new vertex
3. Keep growing until all vertices are reached

```
Growing Animation:

Step 0: Plant seed at A
    (A)   B
          |
     C    D    E

Step 1: Grow to nearest neighbor
    (A)━━(B)          Picked edge A-B (weight 2)
          |
     C    D    E

Step 2: From {A,B}, find nearest outside vertex
    (A)━━(B)          Picked edge B-D (weight 3)
          ┃
     C   (D)   E

Step 3: Continue...
    (A)━━(B)          Picked edge D-C (weight 1)
     ┃    ┃
    (C)━━(D)   E

Step 4: Final tree
    (A)━━(B)          Picked edge D-E (weight 4)
     ┃    ┃
    (C)━━(D)━━(E)

MST Complete!
```

## Prim's Algorithm: Formal Steps

```
PRIM_MST(Graph G, start_vertex):

    // Initialize
    MST = empty set
    visited = {start_vertex}

    while visited ≠ all vertices:

        // Find minimum weight edge (u, v) where:
        //   - u is in visited
        //   - v is NOT in visited

        Find edge (u, v) with minimum weight
              where u ∈ visited AND v ∉ visited

        // Add this edge to MST
        Add (u, v) to MST
        Add v to visited

    return MST
```

```
    A━━━━━━━B━━━━━━━C

    ┃       ┃       ┃

    Also: A-D=6, B-E=8, C-F=5
          D-E=9, E-F=7
```

## Prim's Time Complexity

| Implementation                  | Time Complexity |
| ------------------------------- | --------------- |
| Adjacency Matrix                | O(V²)           |
| Binary Heap + Adjacency List    | O(E log V)      |
| Fibonacci Heap + Adjacency List | O(E + V log V)  |

# 🔶 Kruskal's Algorithm

## The Intuition: Sorting and Merging

Think of Kruskal's like building with LEGO:

1. **Dump all pieces** (edges) on the table
2. **Sort by size** (weight) — smallest first
3. **Pick smallest piece** that connects two separate structures
4. **Skip pieces** that would create loops
5. **Stop** when everything is connected

```
Sorting Animation:

All edges dumped and sorted:

[A-B:1] [B-E:2] [A-D:3] [E-C:3] [B-C:4] [D-E:4] [E-F:5] [A-E:5] [C-F:6]
   ↑       ↑       ↑       ↑                       ↑
 Pick    Pick    Pick    Pick                    Pick
   ✓       ✓       ✓       ✓       Skip(cycle)    ✓

MST complete!
```

## Key Concept: Disjoint Set Union (Union-Find)

To detect cycles, Kruskal's uses a special data structure:

```
Question: If I add edge (u, v), will it create a cycle?
Answer:   Only if u and v are ALREADY in the same component!

Union-Find operations:
- FIND(x): Which component does x belong to?
- UNION(x, y): Merge components of x and y
```

## Kruskal's Algorithm: Formal Steps

```
KRUSKAL_MST(Graph G):

    // Initialize - each vertex is its own component
    MST = empty set
    for each vertex v in G:
        MAKE_SET(v)    // v is in its own component

    // Sort all edges by weight
    Sort all edges in non-decreasing order of weight

    // Process edges greedily
    for each edge (u, v) in sorted order:
        if FIND(u) ≠ FIND(v):   // Different components?
            Add (u, v) to MST    // No cycle will form
            UNION(u, v)          // Merge components

        if |MST| == V - 1:       // MST complete?
            break

    return MST
```

## Kruskal's Time Complexity

```
Step 1: Sort edges        → O(E log E)
Step 2: Union-Find ops    → O(E × α(V)) ≈ O(E)
        (α is inverse Ackermann, practically constant)
─────────────────────────────────────────────────
Total:                    → O(E log E) = O(E log V)
        (since E ≤ V², log E ≤ 2 log V)
```

## Detailed Comparison Table

| Aspect                     | Prim's Algorithm              | Kruskal's Algorithm             |
| -------------------------- | ----------------------------- | ------------------------------- |
| **Approach**               | Vertex-based (grow tree)      | Edge-based (merge forests)      |
| **Starting Point**         | Starts from one vertex        | Considers all edges globally    |
| **Data Structure**         | Priority Queue (Min-Heap)     | Disjoint Set Union (Union-Find) |
| **Edge Selection**         | Min edge from tree to outside | Min edge overall (if no cycle)  |
| **Cycle Prevention**       | Natural (only goes outside)   | Explicit check via Union-Find   |
| **Time (Matrix)**          | O(V²)                         | O(E log E)                      |
| **Time (Adj List + Heap)** | O(E log V)                    | O(E log E)                      |
| **Better for**             | Dense graphs (E ≈ V²)         | Sparse graphs (E ≈ V)           |
| **Needs Sorting?**         | No                            | Yes (sort all edges first)      |
| **Parallelizable?**        | Harder                        | Easier                          |
| **Graph Type**             | Connected only                | Can handle disconnected         |

# 📝 Important Points for MCA Exam

## Key Definitions

### Greedy Algorithm

> An algorithm that makes **locally optimal choice** at each step hoping to find **global optimum**.

### Greedy Choice Property

> A globally optimal solution can be arrived at by making locally optimal choices.

### Fractional Knapsack

> Knapsack problem where fractions of items can be taken. Solved by greedy approach using value/weight ratio.

### Spanning Tree

> A subgraph that connects all vertices with minimum edges (V-1) and no cycles.

### Minimum Spanning Tree

> A spanning tree with minimum total edge weight.

## Formulas to Remember

```
Fractional Knapsack:
    Time Complexity: O(n log n)
    Strategy: Sort by value/weight ratio, pick highest first

MST Properties:
    Edges in MST: V - 1
    For connected graph: Exactly one MST (if all weights unique)

Prim's:
    Time: O(V²) with matrix
    Time: O(E log V) with heap + adjacency list

Kruskal's:
    Time: O(E log E) = O(E log V)
    Uses: Disjoint Set Union (Union-Find)
```

## Common Exam Questions

1. **Prove greedy works for fractional knapsack**
   - Show that taking highest ratio first maximizes value per unit capacity used

2. **Why greedy fails for 0/1 knapsack**
   - Give counter-example showing ratio-based selection gives suboptimal result

3. **Trace Prim's/Kruskal's on given graph**
   - Show step-by-step with visited sets and MST edges

4. **Compare Prim's and Kruskal's**
   - Use the comparison table above

## Quick Revision Checklist

```
✅ Greedy algorithms make local optimal choices
✅ Greedy works when: Greedy Choice Property + Optimal Substructure
✅ Fractional Knapsack: O(n log n), sort by ratio
✅ 0/1 Knapsack: Greedy fails, needs Dynamic Programming
✅ MST has exactly V-1 edges
✅ Prim's: Grow tree from vertex (use Min-Heap)
✅ Kruskal's: Sort edges, merge forests (use Union-Find)
✅ Both give same MST, different approaches
✅ Dense graph → Prim's, Sparse graph → Kruskal's
```
